# Factory OS — Industrial IoT & OT Connectivity Architecture

**Author:** Principal Engineering Lead  
**Specification:** Telemetry Streaming, Edge Connector Architecture, Simulation vs Live Data

---

## 1. Overview

Factory OS supports real-time industrial telemetry ingestion via WebSockets and Server-Sent Events (SSE). To ensure data integrity, the platform strictly distinguishes between **SIMULATION MODE** and **LIVE OT MODE**.

---

## 2. Telemetry Streaming API Contracts

### 2.1 WebSocket Telemetry (`/api/v1/stream/telemetry/{machine_id}`)
Every streaming frame emitted over WebSockets includes an explicit data envelope:

```json
{
  "mode": "SIMULATION",
  "data_source": "synthetic_random_generator",
  "note": "Connect a real OPC-UA/MQTT edge gateway to replace this stream. See docs/iot/README.md",
  "machine_id": "mch_104",
  "timestamp": "2026-08-28T20:15:00.000Z",
  "vibration_mm_s": 4.12,
  "temperature_deg_c": 64.5,
  "hydraulic_pressure_bar": 195.0,
  "rpm": 1200,
  "status": "Running",
  "quality_flag": "SIMULATED"
}
```

### 2.2 Telemetry Quality Flags
Production IoT deployments must tag each reading with standard sensor quality flags:
- `GOOD`: Verified reading within sensor calibration bounds.
- `UNCERTAIN`: Reading out of nominal range or clock sync jitter detected.
- `BAD`: Sensor failure, wire disconnect, or out-of-range value.
- `STALE`: Telemetry heartbeat delayed > 5.0 seconds.
- `SIMULATED`: Generated by synthetic data stream.

## 4. Edge Resilience Rules

1. **Network Disconnection**: Edge gateway buffers telemetry locally in append-only storage.
2. **Re-connection**: Flushes buffered records with `is_backfill: true` metadata flag.
3. **Duplicate Prevention**: Message deduplication using `(device_id, sensor_id, timestamp_utc)` composite key.
4. **Clock Jitter**: Edge gateway attaches UTC timestamp at capture time rather than arrival time.
